# Slax PWA (iPhone, Android, desktop) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Slax installable and pleasant on iPhone, Android and desktop as a Progressive Web App (no native wrappers), with Web Push notifications, so the author's family can use it for real and test it.

**Architecture:** The existing Preact SPA gains a web app manifest, icons, a hand-written service worker (app-shell precache, never caching API / private data / files), install UX, mobile/safe-area polish, and Web Push (VAPID) delivered by a queued Laravel job. No new service; no native app store work. Stays within the existing Helm chart, CSP and Caddy/nginx path.

**Tech Stack:** Preact + Vite + TypeScript (Vitest, Playwright incl. WebKit/Pixel emulation), Laravel 12 (minishlink/web-push or equivalent), Redis queue, Helm chart.

**Spec:** `docs/superpowers/specs/` (Slax v1 design). This plan extends v1 scope by the user's explicit request of 2026-10-31 ("android, desktop et iphone, toute ma famille dessus pour tester"). Calls stay v2. Branch `build/pwa` (worktree `/home/yechpa/Documents/slax-pwa`), based on `build/v1` @ 0620e45.

## Global Constraints

- Branch `build/pwa` only. Do NOT push, do NOT create tags, no AWS / slax-dev access, no real secrets in the repo. The Telegram token and chat id never appear in any file. VAPID private keys are generated per environment and live only in Kubernetes secrets (placeholders/dev-only generated keys in examples, never real ones).
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; author identity `yechpa <yechpa@gmail.com>` (use `git -c user.name=yechpa -c user.email=yechpa@gmail.com commit`).
- Locales en / he (RTL) / fr: every new string in all three, key-parity test green. Logical CSS properties only (no left/right).
- Themes: dark "Console" and light "papier listing". `theme-color` follows the active theme.
- CSP stays `default-src 'self'` with no `unsafe-inline`; the manifest, service worker and icons are same-origin. Files are served from presigned S3 URLs on another origin: the service worker MUST NOT intercept or cache cross-origin requests, `/api/`, `/auth/`, `/broadcasting/`, `/app/` (WebSocket), or any response with `Set-Cookie`/private data.
- The service worker never makes Slax show another user's data after sign-out: nothing authenticated is cached; sign-out clears any caches the app owns.
- The fake IdentityProvider triple gate and the `VITE_E2E` guard keep working; production bundles contain no e2e route string.
- Push payloads never contain message bodies, e-mail addresses, or file names. Banned users get no push. Push respects presence (no push to a user who has a visible, connected tab).
- Existing gates stay green: `make lint`, `make test`, `make chart-lint`, `make e2e`, `make proxy-test`.
- Docs honesty: say what was verified only in emulation (WebKit/Pixel emulation, no real iPhone/Android device) and what needs a real device.
- Budget: no new always-on service, no new paid AWS component.

## Review Focus

1. A stale service worker serving an old app shell against a newer API after a deploy (user stuck on a broken version): the update flow must be visible and safe.
2. Sign-out on a shared family device: no cached private data, push subscription removed for that user/device.
3. iPhone Safari quirks: input zoom under 16px, 100vh vs dynamic viewport, keyboard covering the composer, notch/home-indicator safe areas, RTL on mobile.
4. Push to dead subscriptions (404/410) and to users who left a channel / were banned / were removed from a private channel.
5. Family accounts being wiped by the nightly demo reset.

### Task 18: Web Push notifications (VAPID), privacy-preserving

**Files:**
- Create: migration `push_subscriptions(id, user_id fk cascade, endpoint text unique, p256dh, auth, locale, user_agent_hash?, created_at, last_used_at)`; `App\Models\PushSubscription`; `App\Services\Push\WebPushSender` (interface + implementation using a maintained Web Push library; a fake in tests); `App\Jobs\SendPushNotification`; `App\Http\Controllers\PushSubscriptionController`; `lang/{en,he,fr}/push.php`; Pest tests; `frontend/src/pwa/push.ts`, settings UI toggle + test button, SW `push` and `notificationclick` handlers (extend the SW from Task 16 without breaking its tests); i18n strings; chart/secret wiring; `docs/runbook.md` section
- Modify: message creation path (dispatch after commit), `deploy/helm/slax/**` (VAPID public/private/subject through the existing Secret and ConfigMap pattern; `create-secrets.sh` gets a VAPID key generator step), `deploy/helm/check-chart.sh`, `.env.example` (empty VAPID keys), `docs/known-limitations.md`

**Interfaces:**
- Produces: `GET /api/v1/push/public-key` (VAPID public key), `POST /api/v1/push/subscriptions {endpoint, keys:{p256dh,auth}}` (max 10 per user, upsert by endpoint), `DELETE /api/v1/push/subscriptions` (by endpoint, own only), `POST /api/v1/push/test` (sends a test push to the caller's own subscriptions, throttled). Trigger rules: push on (a) a new message in a DM or group DM, (b) a message that @mentions the user, (c) a reply in a thread the user started or replied to. Never for the author's own messages, never to a banned user, never to a non-member of the channel, never when the user has a connected presence session with a visible tab (use the existing presence service; if "visible" is unknown server-side, use "has an active websocket presence in the last 60 s" and document). Payload (encrypted by the Web Push protocol): `{type, title, body, url, tag}` where title = localized "sender in #channel" or "sender (direct message)", body = a short localized generic line ("New message", "You were mentioned", "New reply") and NEVER the message text; `url` = in-app path; `tag` = conversation id (collapse). Expired subscriptions (404/410) are deleted; other failures retried by the queue with backoff, then dropped; a failed push never breaks message sending.

- [ ] **Step 1: Failing tests first (Pest)**: subscribe/unsubscribe/limit/ownership/auth; banned user and non-member get nothing; author gets nothing; presence-active user gets nothing; DM, mention and thread-reply each dispatch exactly one job per target subscription; payload has no body text/e-mail/file name (assert on the exact payload keys); 410 deletes the subscription; sender failure does not fail `POST /messages`; locale-specific text picked from the subscription's `locale`.
- [ ] **Step 2: Failing tests first (Vitest)**: push.ts permission flow (must be triggered by a user gesture, iOS requires installed standalone: show the "install first" help otherwise), subscribe/unsubscribe calls, sign-out unsubscribes this device and calls DELETE; SW `push` handler always calls `showNotification` (userVisibleOnly), `notificationclick` focuses an existing window or opens the `url`, ignores a `url` that is not a same-origin path.
- [ ] **Step 3: Implement** server and client. VAPID keys read from env; if unset, push is disabled cleanly (public-key endpoint returns 404/204, UI hides the toggle) so dev and e2e work without keys. An artisan command `slax:push-keys` prints a fresh VAPID pair (never writes files).
- [ ] **Step 4: Chart and secrets**: keys in the Secret only (not ConfigMap), subject `mailto:` from values, queue worker unchanged; `check-chart.sh` asserts private key never in a ConfigMap; `create-secrets.sh` can set `VAPID_PRIVATE_KEY`/`VAPID_PUBLIC_KEY` using the command above.
- [ ] **Step 5: Runbook** section: generate keys, set secrets, rotate (rotation invalidates subscriptions: users re-enable), test with the test button, iOS requirements, dead-subscription cleanup. State plainly that real delivery to Apple/Google push services was NOT tested here.
