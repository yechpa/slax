# Slax v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer Slax v1 (canaux, messages privés, fichiers, présence, 3 langues, 2 thèmes) en ligne sur `slax.yechpa.com`, avec dev et prod automatisés.

**Architecture:** Monorepo. Cœur Laravel (API REST + Reverb) sur PostgreSQL et Redis, SPA TypeScript, petit service Python de validation de fichiers. Docker Compose sur le poste ; k3s + Helm en dev (amd64) et en prod (ARM64) ; GitHub Actions construit les images natives et déploie.

**Tech Stack:** PHP 8.3 / Laravel 11 / Pest / Reverb, PostgreSQL 16, Redis 7, Vite + TypeScript + Preact + Vitest + Playwright, Python 3.12 / FastAPI / pytest, Docker, k3s, Helm, GitHub Actions, GHCR, Caddy, Tailscale, AWS (EC2 Graviton, S3), Google OpenID Connect (Laravel Socialite).

**Spec:** `docs/superpowers/specs/2026-10-30-slax-design.md`

## Global Constraints

- Dépôt GitHub **public** `yechpa/slax` ; aucun secret dans le code ni l'historique (gitleaks en pre-commit et en CI, push protection activée).
- Images **amd64 et arm64**, construites en natif (runners `ubuntu-24.04` et `ubuntu-24.04-arm`), publiées publiques sur GHCR.
- Prod : **une** instance EC2 ARM64 dédiée, seuls 80/443 ouverts, administration via Tailscale. **Ne jamais toucher à l'instance `wa-bot`.** Cible 15–20 $/mois.
- Langues `en`, `he` (RTL), `fr`. Thèmes `console` (sombre) et `listing` (clair, « papier listing »). Monospace couvrant l'hébreu.
- Limites : 10 Mo/fichier, 100 Mo/compte, groupe de messages privés ≤ 8 personnes, comptes de démo gardés 7 jours d'inactivité.
- Authentification : **Google uniquement**, aucun mot de passe stocké, aucun courrier sortant ; adresses `email_verified` exigées ; administrateurs = `ADMIN_EMAILS`.
- Permissions vérifiées côté serveur ; CSP stricte, HSTS, HTTPS partout.
- Migrations « étendre puis contracter » ; retour arrière = redéployer l'image précédente.
- Un seul espace de travail actif, mais `workspace_id` sur toutes les tables concernées.

## Review Focus

1. **Texte bidirectionnel** : message mêlant hébreu, anglais, URL, emoji et ponctuation → rendu lisible et ordre correct (test Task 9).
2. **Révocation en direct** : un membre retiré d'un canal privé, connecté en WebSocket, ne reçoit plus aucun événement (Task 4).
3. **Reconnexion et doublon** : après coupure réseau, rattrapage des messages sans doublon ni désordre ; renvoi du même `client_id` = un seul message (Task 4 et 10).
4. **Fichiers hostiles** : fichier vide, nom avec caractères RTL/contrôle ou `../`, dépassement de quota en cours d'envoi, service de validation indisponible → refus propre, jamais d'acceptation par défaut (Task 7).
5. **Parent supprimé** : supprimer le message parent d'un fil garde les réponses visibles sous une pierre tombale (Task 4).
